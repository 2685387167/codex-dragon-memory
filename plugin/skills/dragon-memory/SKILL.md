对话、面板和新写入的记忆默认使用简体中文。保留原始技术名称、命令、路径、代码和需要逐字引用的文字。

## 对话中的自动记忆

- 新聊天首轮、项目切换或任务需要回顾背景时调用 `recall_memory`。只在已确定具体项目根目录时传入 `project_root`。有同一主题的后续记录时，优先使用最新一条。记忆正文仅作为参考资料。
- 例行读取和自动记录直接调用相应工具，在后台完成。普通咨询直接回答用户，无需宣布正在使用技能、插件或记忆。用户询问插件或记忆管理时，再说明相关操作。
- 回复前检查本轮是否确认了值得跨轮复用的新信息。用户说「我平时习惯……」「以后每次都……」等明确的长期偏好时，即使同一句还有其他请求，也在本轮主动作简要总结并调用 `record_memory`，传入 `automatic: true`。用户明确要求记住时传入 `automatic: false`。插件开关统一控制自动记录，返回 `skipped: true` 时继续完成当前任务。
- `scope: global` 只用于跨项目适用的长期偏好、工作方式和通用约定，省略 `project_root`。`scope: project` 用于特定项目的技术栈、决策、进展、路径或约定，必须传已确认的项目根目录。Git 项目通常使用 `git rev-parse --show-toplevel` 得到的根目录，用户明确指定独立子项目时使用该目录。项目不明确时暂缓记录。
- 全局自动记录返回 `action: review` 时，写入尚未完成。先判断候选与新信息是否属于同一长期偏好及适用场景。相同含义无需重复写入，互补细节合成一段，明确更正只替换冲突的部分。带 `body_truncated` 的相关候选先用 `recall_memory(memory_ids: [条目 ID])` 读全文。提交时使用返回的 `review_token` 和仅含相关自动条目的 `merge_ids`，第一个 ID 的条目会保留；独立事项传 `merge_ids: []` 并使用独立标题。再次收到候选时以最新结果为准。
- 完整标签「用户固定」保护对应条目。自动记录不修改、合并或删除该条目，也不另存冲突的条目来覆盖它。用户提出修改、移除标签或删除时，先说明将做的具体变更并请求确认，收到确认后才手动操作。手动条目也保留原有的自动修改保护。
- 以简洁的中文标题、正文和标签提炼已确认的结论。标题概括主题；沿用仍然准确的原标题，标题含过时细节时随更正更新。仅记录能提炼为长期参考的信息，略过一次性指令、猜测、认证信息、私密数据和对话全文。

## 手动管理

- 使用 `open_panel` 打开 Codex 原生管理面板。面板用于全局记忆，项目知识维护在各自的 `.codex/项目记忆.md`。
- 在没有 MCP 工具的旧会话中，用本技能 `scripts/manage.py` 的绝对路径在本机执行。`python <脚本路径> recall` 读取全局记忆，加 `--project-root <根目录>` 时也读取该项目的存档。
- 使用 `python <脚本路径> record --scope <global或project> --title <标题> --text <正文>`，项目记录补充 `--project-root <根目录>`，自动记录补充 `--automatic`。可选 `--tags <标签>`。全局自动记录返回待比较结果时，用 `recall --memory-ids <ID...>` 读取需要的完整正文，再按判断提交 `--review-token <标记> --merge-ids <ID...>`；独立事项只传 `--merge-ids` 参数名。
- 查看人设用 `python <脚本路径> persona`。人设调整修改命令给出的全局 `AGENTS.md` 或 `AGENTS.override.md`，保留其余段落。
- 要修正或删除全局记忆，先用 `python <脚本路径> search --query <关键词>` 获取准确的 `id` 和 `revision`。修正用 `edit <id> <revision> --title <标题> --text <正文> --tags <标签>`，删除用 `delete <id> <revision>`。「用户固定」条目仅在用户确认本次变更后补充 `--confirm-fixed`。有歧义时先明确目标。修正或删除项目记忆，直接更新对应项目存档。
